# Design decisions and changes

`project.md` is the original brief and `project v0.1.2.md` is the feature list
it grew into. Neither explains *how* those features actually got built, or the
bugs and infrastructure work that happened alongside them. This file is that
record — what was decided, why, and what's worth revisiting. Roughly
chronological within each section.

## Terminology and layout fixes

- **"Project" → "Font" throughout the UI.** The File menu, dialog titles, file
  filters and error messages originally mixed "Project" (Open/Save/Save As)
  with "Font" (New Font, Export Font), left over from when the concepts were
  named separately during early development. Everything user-facing now says
  "Font" — `Open Font…`, `Save Font`, the file-type filter is "Bitmap Font" —
  while internal identifiers (`projectPath`, `ProjectFile`, `parseProject`, the
  `project:*` IPC channels) were deliberately left alone: renaming them was a
  large, risky diff for zero user-visible benefit.
- **Two real CSS layout bugs**, found by actually resizing the window rather
  than by reading the stylesheet:
  - `#app` had `grid-template-rows` but no `grid-template-columns`, so its
    implicit column was `auto` — sized to content and free to grow wider than
    the window. At certain sidebar widths this pushed the character map and
    the toolbar's right-hand glyph readout off the visible edge, silently
    eaten by `overflow: hidden` on `<body>`. Fixed with an explicit
    `grid-template-columns: minmax(0, 1fr)`.
  - The sidebar's `--sidebar-width` custom property had no upper bound, so a
    wide drag followed by shrinking the window could leave the character map
    demanding more space than existed. Fixed with
    `clamp(180px, var(--sidebar-width, 320px), 60%)`, and the splitter's own
    drag ceiling was lowered from 70% to 60% to match where the clamp actually
    stops.

## Packaging and distribution

- **Electron ships with no OS-native "run this on my machine" story**, so a
  meaningful chunk of early work was making the project buildable and
  installable at all: documented Node/npm version requirements
  (`engines` in `package.json`), the ~100MB Electron postinstall download and
  how to skip it (`ELECTRON_SKIP_BINARY_DOWNLOAD=1`, since nothing under
  `test/` imports Electron), and Linux/WSL system library requirements.
- **`electron-builder.yml` added from scratch** — the dependency was already
  in `package.json` but unconfigured, so there was no way to produce an
  installer. Targets NSIS (Windows), DMG (macOS), AppImage (Linux). Only
  `out/**` and `package.json` are packed into the asar; everything else is a
  devDependency, so `node_modules` never ships.
- **The NSIS build needs symlink privilege** (Windows Developer Mode, or an
  elevated shell) because electron-builder's `winCodeSign` helper archive
  contains macOS symlinks. This is an electron-builder implementation detail,
  not something this project controls — documented in the README rather than
  worked around.
- **Placeholder app icon**, generated by `scripts/make-icon.mjs` rather than
  drawn in an image editor — a hand-rolled PNG writer (~150 lines, no
  dependency) drawing an 8×8 grid with a capital A and the accent-colored
  advance marker, in the app's own palette. Exists mainly to stop Electron's
  default icon from shipping as the app's identity; not meant to be final art.
- **CI (`.github/workflows/ci.yml`)**: typecheck + tests + build on Node
  18/20/22, skipping the Electron binary download. **Release
  (`.github/workflows/release.yml`)**: triggered by pushing a `vX.Y.Z` tag,
  builds all three platforms on their native runners, assembles a **draft**
  release first and only publishes once every platform succeeds — so one
  platform failing can't leave a half-populated public release. The tag is
  checked against `package.json`'s version before anything builds.
- **Nothing is code-signed.** Windows installs show a SmartScreen warning;
  macOS builds need `xattr -dr com.apple.quarantine` after download to bypass
  Gatekeeper. Fixing either needs a paid certificate (Authenticode; Apple
  Developer Program for notarization) — a cost/process decision left to
  whoever ships this for real, not something to default into.
- **`.vscode/launch.json` is tracked**, unlike the rest of `.vscode/` (personal
  editor state, gitignored) — carved out with a `.gitignore` negation pattern.
  It's a shared way to run the app (F5 → "Electron: Main" attaches the
  debugger to the main process; "Electron: Main + Renderer" adds a Chrome
  attach on port 9222 for renderer breakpoints), not a personal preference.
- **`sample/` is bundled via `extraResources`**, not `files` — it lands
  unpacked next to `app.asar` in the installed app (`resources/sample/`)
  rather than inside the archive, so it stays a normal, browsable folder.
  Help ▸ Open Sample Fonts Folder points straight at it via
  `shell.openPath()`; the path resolves differently in dev
  (`<project>/sample`) vs. packaged (`process.resourcesPath/sample`), handled
  in `src/main/paths.ts`.
- **In-app documentation viewer.** `docs/user-guide.md` and
  `docs/file-formats.md` are converted to standalone HTML at build time
  (`scripts/build-docs.mjs`, using `marked` — a zero-dependency devDependency,
  not a runtime one) and opened in a separate `BrowserWindow` from Help ▸ User
  Guide / File Formats Reference. Chosen over rendering markdown live in the
  renderer because the content never changes at runtime, so pre-rendering
  keeps the docs viewer script-free (`script-src 'none'` in its own CSP) and
  avoids adding a markdown-rendering dependency to the shipped app at all —
  `marked` only ever runs in the build step. Heading IDs and `.md`→`.html`
  cross-links are generated by a small custom `marked` renderer, since `marked`
  itself stopped auto-generating heading anchors in recent major versions.
  Runs automatically before both `dev` and `build` via npm's `predev`/
  `prebuild` hooks, so the in-app copy can't go stale relative to the source
  markdown.

## v0.1.2 feature choices worth flagging

These four features (raw font import, font metadata, system-font fill,
character-map overflow rendering) came from `project v0.1.2.md`, but several
required judgment calls the spec didn't spell out.

- **Raw import's "row vs. column" byte layout is a guess.** The spec asked for
  a row/column choice but didn't define column-major precisely. The
  implementation (`io/rawImport.ts`) treats both as the *same* total bytes per
  character, just sequenced differently: row-major is this app's own `.bin`
  layout (each row is `bytesPerLine` consecutive bytes); column-major keeps
  the same byte count but groups by 8px-wide band instead, top to bottom. This
  is **not** the more common GLCD/Adafruit-style column format (one byte = one
  8px-tall vertical strip, independent of `bytesPerLine`), which would need an
  extra "width in pixels" field the spec's dialog doesn't have room for. The
  two interpretations are identical for any font ≤8px wide and only diverge
  for wider fonts — worth revisiting against a real ROM dump if an import ever
  looks transposed.
- **Font metadata scope was deliberately narrow.** Of the fields listed under
  "New Font" in the spec, only name/author/email/description/created/modified
  are persisted (`FontMetadata` in `shared/types.ts`). Cell width/height,
  first/last codepoint, and the codepoint mapping are creation-time
  conveniences only — not stored, because they're already
  "configurable elsewhere" (Font ▸ Dimensions, Add/Remove Codepoint) and
  storing a second copy would just create a way for it to drift from the
  truth. Font Properties always computes cell size and codepoint range fresh
  from the live document rather than remembering what was typed at creation.
- **Fixed-width is derived, not stored — and this was a correction.** It
  started as a `metadata.fixedWidth` checkbox in New Font, matching the spec's
  wording literally. That was replaced: the checkbox is gone, and Font
  Properties now computes "Fixed width: Yes/No" by checking whether every
  defined glyph's advance equals the cell width. A declared flag can lie the
  moment a single glyph is resized; a computed one can't.
- **`created`/`modified` are stamped by the save path, not the metadata
  dialog.** `created` is set once, on the first successful save by any path
  (Save or Save As), and never reset afterward; `modified` updates on every
  save after that. The Font Properties dialog's confirm button is labeled
  "Apply" rather than "Save" specifically to avoid implying that closing the
  dialog itself persists anything to disk.
- **System-font fill is implemented but disabled.** `Helpers ▸ Fill From
  System Font…` rendered an installed font straight into the grid via Canvas
  2D, with a two-pass supersample-then-downsample rasterization step added
  later to improve small-size quality. It was switched off (menu item removed,
  code left in place in `model/systemFont.ts` / `ui/systemFontFill.ts` /
  `main.ts`) because Canvas 2D has no API for TrueType hinting, and even with
  supersampling the results at 8–16px are visibly rougher than a real
  hinting-aware rasterizer (FreeType, or similar) would produce. Re-enabling
  it needs either an acceptance that quality is "good enough," or a
  different rendering approach entirely.
- **Character map overflow rendering only touches the sidebar thumbnails.**
  The spec asked for the region past a glyph's advance width to render in
  dark red rather than disappearing. This only applies to the character map's
  thumbnails (`ui/draw.ts`'s `drawGlyphWithOverflow`, used only from
  `ui/glyphlist.ts`) — the bottom preview strip was deliberately left alone,
  since it lays out continuous running text with no fixed per-character cell
  to show overflow *within*.

## Smaller, later refinements

- **Window title composes as `Font Name (filename.fnt.json)`** once the font
  has a name, falling back to just the filename otherwise — added after
  Font Properties existed, since there was suddenly a name worth showing.
- **The Save dialog suggests a filename from the font's name** on the very
  first save only (`src/main/fileNaming.ts`), sanitized for the current
  platform (Windows gets the fuller treatment — reserved device names,
  trailing dot/space stripping — since that's the platform with real
  filename restrictions beyond `/` and NUL). Once a file has a real path,
  that path always wins over the suggestion, including on Save As.
- **Left/right column guide visibility moved from a global app preference to
  per-document state**, saved with the font (`FontDoc.showLeftColumn`/
  `showRightColumn`), defaulting to hidden. Cap height/x-height/baseline
  visibility stayed as a global preference, since those are relevant to
  virtually any font, unlike the column guides, which only matter to a font
  actually using the narrower-cell-inside-a-wider-cell technique. This
  required a small bidirectional sync: the renderer tells main the current
  document's state after every load (New Font, Open Font, Undo/Redo) and
  after every toggle, and main rebuilds the View menu's checkboxes from it —
  because Electron's native menu is main-process state, but the truth it now
  reflects lives in the renderer's document.
